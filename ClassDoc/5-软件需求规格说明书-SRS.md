## 1. 引言

### 1.1 目的

本文档定义本系统的**功能需求**、约束与验收标准，作为需求基线冻结依据，供设计、开发、测试与客户验收引用。非功能项见第 4 章说明：**无硬性指标、不纳入基线验收**。

### 1.2 范围

系统面向 K12 课外辅导场景，服务约 300 名课程顾问及管理层，通过企业微信侧边栏与管理后台，提供：

1. AI 客户画像生成与确认
2. AI 智能回复建议（销售 / 客服）
3. AI 智能标签推荐
4. AI 智能日程与提醒
5. 管理后台（组织、客户、订单、标签、看板、AI 采纳率）
6. 企业微信侧边栏集成

**明确不做（本期）**：

- AI 自动代发消息 / 自动替顾问决策
- 替换企业微信主聊天能力
- 开局完整微服务拆分（MVP 采用轻量单体 + 模块化）
- **数据安全专项**（加密加固、操作审计、隐私合规认证、数据出境评估等）：客户未提出明确要求，**本期不交付、不验收**；避免无需求承诺
- **非功能量化 SLA**（响应时延、可用性百分比等）：客户未提出硬性要求，**不纳入基线验收**



### 1.3 用户与干系人


| 角色         | 说明           | 主要诉求              |
| ---------- | ------------ | ----------------- |
| 课程顾问       | 一线销售/服务人员    | 侧边栏看画像、拿话术、管标签与提醒 |
| 区域主管       | 区域管理         | 看团队人效、转化、AI 采纳情况  |
| 超级管理员 / 运营 | 总部管理与运营      | 标签体系、权限、全局看板      |
| 家长/学员      | 间接用户（企微沟通对象） | 不直接登录本系统          |




### 1.4 产品原则（基线约束）

1. **重建议、轻代劳**：AI 输出均为建议/草稿，人工确认后生效；最终发送责任在使用者。
2. **界面标注**：AI 生成内容须明确标注「AI 建议」。
3. **三目标**：新人快速上手、老人效率翻倍、管理层看得清楚。

## 2. 总体描述



### 2.1 业务背景与痛点


| 痛点                 | 影响        | 对应能力           |
| ------------------ | --------- | -------------- |
| 客户信息分散、离职断层        | 接手从零问起    | 360° 画像 + 草稿确认 |
| 新人转化率约资深 1/3       | 人效下降      | 智能回复建议         |
| 标签各自为政             | 总部数据不可用   | 统一标签 + AI 推荐   |
| 每人跟进 200–400 客户易遗漏 | 错过试听/续费窗口 | 智能日程与提醒        |
| 售前售后数据孤岛           | 无完整生命周期视图 | 多源抽取 + 管理后台    |




### 2.2 系统上下文

```
企业微信（聊天 / 日历 / 身份）
        │
        ▼
┌───────────────────┐     ┌──────────────────┐
│ 企微侧边栏 H5      │◄───►│ 业务 API（单体）  │
│ 画像/话术/标签/日程 │ SSE │ 权限 / 确认流     │
└───────────────────┘     │ AI 编排 Pipeline  │
                          └────────┬─────────┘
        ┌──────────────────────────┼──────────────┐
        ▼                          ▼              ▼
   管理后台 Web              LLM / ASR / RAG    业务数据库
```

## 3. 功能需求

需求编号规则：`FR-<模块>-<序号>`
优先级：P0（MVP 必须） / P1（二期） / P2（三期）

### 3.1 模块 M1：AI 客户画像生成


| 编号            | 需求描述                              | 优先级 | 验收要点                      |
| ------------- | --------------------------------- | --- | ------------------------- |
| FR-PROFILE-01 | 从企微聊天记录、订单数据、客服记录中自动抽取结构化客户信息     | P0  | 至少覆盖三类数据源中的已对接源；抽取结果可追溯来源 |
| FR-PROFILE-02 | 生成 360° 画像：基本信息、学情分析、沟通偏好、跟进历史时间线 | P0  | 四类信息分区展示完整                |
| FR-PROFILE-03 | AI 生成画像默认「草稿」状态，顾问确认后生效           | P0  | 未确认不对业务统计生效；确认有操作记录       |
| FR-PROFILE-04 | 每次 AI 分析展示置信度与信息来源                | P0  | 侧边栏/详情页可见置信度与来源           |
| FR-PROFILE-05 | 聊天中出现新信息时，系统可更新画像建议（草稿增量）         | P0  | 新建议不覆盖已确认字段，除非顾问再次确认      |
| FR-PROFILE-06 | 顾问可在侧边栏查看并编辑/确认画像字段               | P0  | 支持字段级确认与驳回                |




### 3.2 模块 M2：AI 智能回复建议


| 编号          | 需求描述                          | 优先级   | 验收要点                   |
| ----------- | ----------------------------- | ----- | ---------------------- |
| FR-REPLY-01 | 基于客户画像与当前聊天上下文推荐回复话术          | P1    | 建议与上下文相关，界面标注 AI 建议    |
| FR-REPLY-02 | 区分销售回复建议（转化/逼单）与客服回复建议（服务/留存） | P1/P2 | 销售 P1；客服 P2；场景可切换或自动识别 |
| FR-REPLY-03 | 区分小学 / 初中 / 高中等教学阶段关注点差异      | P1    | 同学段问题建议侧重点不同（抽检）       |
| FR-REPLY-04 | 语音消息自动转文字后再做语义分析与建议           | P2    | 语音可转写；转写失败有提示          |
| FR-REPLY-05 | 建议仅供参考，须顾问手动发送；系统不自动代发        | P1    | 无自动发送接口；发送动作在企微侧由人完成   |
| FR-REPLY-06 | 支持顾问对建议「采纳 / 拒绝 / 编辑后使用」并埋点   | P1    | 后台可统计采纳率               |




### 3.3 模块 M3：AI 智能标签推荐


| 编号        | 需求描述                 | 优先级            | 验收要点              |
| --------- | -------------------- | -------------- | ----------------- |
| FR-TAG-01 | 根据聊天行为与画像特征推荐添加/移除标签 | P1             | 推荐理由可见；需确认        |
| FR-TAG-02 | 管理后台支持自定义标签体系        | P0（体系）/ P1（推荐） | MVP 可先手工维护标签；推荐二期 |
| FR-TAG-03 | 标签可配置关联跟进 SOP        | P1             | 标签详情可见 SOP 说明     |
| FR-TAG-04 | 标签推荐须顾问确认后生效         | P1             | 未确认不写入正式标签        |
| FR-TAG-05 | 标签数据支持统计分析           | P0/P1          | 后台可按标签看客户分布       |




### 3.4 模块 M4：AI 智能日程与提醒


| 编号          | 需求描述                      | 优先级 | 验收要点           |
| ----------- | ------------------------- | --- | -------------- |
| FR-SCHED-01 | 识别聊天中的时间意图，创建待办/提醒建议      | P2  | 典型语句可解析并生成待办草稿 |
| FR-SCHED-02 | 基于历史数据预测续费、试听回访等节点并创建日程建议 | P2  | 可生成周期性/预测类提醒   |
| FR-SCHED-03 | 日程同步到企业微信日历               | P2  | 授权用户日历可见对应日程   |
| FR-SCHED-04 | 分级提醒：高优先级强提醒，一般事项侧边栏弱提示   | P2  | 两类提醒行为可区分      |
| FR-SCHED-05 | 用户可自定义提醒偏好；遵循最小通知原则       | P2  | 偏好可配置并生效       |
| FR-SCHED-06 | 日程默认按顾问本人视角展示（与后台角色能力一致） | P2  | 与 FR-ADMIN-02 角色能力对齐即可；不做安全专项验收 |

| 编号          | 需求描述                                | 优先级    | 验收要点             |
| ----------- | ----------------------------------- | ------ | ---------------- |
| FR-ADMIN-01 | 员工管理：顾问信息、组织架构                      | P0     | 可增删改查顾问与组织       |
| FR-ADMIN-02 | 角色权限：至少超级管理员、区域主管、普通顾问；按功能模块与数据范围控制 | P0     | 三角色权限差异可验证       |
| FR-ADMIN-03 | 客户管理：列表、画像查看、沟通记录回溯                 | P0     | 可按权限查看客户与记录      |
| FR-ADMIN-04 | 订单管理：订单列表与客户关联                      | P0     | 订单可关联到客户画像       |
| FR-ADMIN-05 | 标签管理：体系定义与统计分析                      | P0     | 可定义标签并看分布        |
| FR-ADMIN-06 | 数据看板：转化漏斗、续费率、顾问人效                  | P0（基础） | MVP 至少含人效与基础转化指标 |
| FR-ADMIN-07 | AI 使用分析：采纳率等埋点报表                    | P1     | 可按顾问查看采纳率        |




### 3.6 模块 M6：企业微信侧边栏集成

| ---------- | ---------------------------- | ----- | ----------------- |

## 4. 非功能需求（不纳入基线）

**口径（已与内部评审对齐）**：客户对非功能**无硬性要求**；对**数据安全无明确要求**。因此：

1. 本章**不作为需求基线、不作为合同/验收条款**，也不单独编号为可验收的 `NFR-*` 硬性条目。
2. 性能数值、可用性百分比、安全加固、审计、隐私合规、数据出境等，**本期不做专项承诺**；实现中仅按常规工程习惯处理，不以验收卡点。
3. 若客户后续**书面**提出非功能或安全要求，再走需求变更纳入基线。

**与「非功能」易混淆、但仍属功能/产品原则的内容**（继续按第 3 章 / §1.4 验收）：

| 内容 | 归属 | 说明 |
|------|------|------|
| AI 建议标注、不代发 | 产品原则 / 功能 | 会议明确共识，属功能行为 |
| 管理后台三角色与数据可见范围 | 功能（FR-ADMIN-02） | 业务权限配置，**不等于**数据安全专项 |
| SSE 流式推送可用 | 功能（FR-SIDE-03） | 验收「通路可用」，**不绑定**时延数值 |

**实现参考（非验收）**：侧边栏交互尽量顺畅；AI 异常时尽量不影响企微主聊天体验；架构保持可迭代即可。

## 5. 数据需求（概要）



### 5.1 核心实体


| 实体            | 关键字段（示意）                                   |
| ------------- | ------------------------------------------ |
| 顾问 User       | id, 企微 userid, 角色, 组织, 提醒偏好                |
| 客户 Customer   | id, 外部联系人 id, 基本信息, 负责人                    |
| 画像 Profile    | customer_id, 版本, 状态(草稿/已确认), 分区内容, 置信度, 来源 |
| 标签 Tag / 客户标签 | 标签定义、SOP、客户绑定、来源(人工/AI)、状态                 |
| 建议 Suggestion | 类型(话术/标签/日程), 内容, 状态, 采纳结果                 |
| 日程 Schedule   | 时间, 类型, 优先级, 同步状态                          |
| 订单 Order      | 客户关联, 金额, 状态, 时间                           |
| 埋点 Event      | 用户, 动作, 对象, 时间                             |




### 5.2 画像状态机

```
AI 生成/更新 → 草稿(draft) → 顾问确认 → 已生效(confirmed)
                    ↓
                 顾问驳回 → 废弃/保留历史版本
```

## 8. 验收标准（基线）



### 8.1 MVP 验收（必须）

1. 侧边栏可对当前客户展示画像草稿，支持确认/编辑。
2. 管理后台可完成员工、客户、订单、标签基础管理及基础看板。
3. 三角色（超管 / 区域主管 / 顾问）业务权限可演示通过（功能范围，非安全专项）。
4. AI 内容均标注「AI 建议」；无自动代发。
5. SSE 推送通路可用（不验收具体时延指标）。

**明确不验收**：性能 SLA、数据安全专项、审计/合规认证、可用性百分比等非功能量化项。

### 8.2 二期 / 三期验收

按第 3 章对应优先级**功能**需求条目逐条验收；试运行以 30 人反馈与关键功能缺陷闭环为准。非功能不单独设验收项。
