# 前端 UI/UX 改进方案

**项目**：擎天学智 · K12 用户画像推荐系统  
**文档编号**：ClassDoc/25  
**版本**：V1.0  
**编制日期**：2026-08-12  
**范围**：`apps/sidebar`、`apps/admin`  
**约束**：**仅方案文档，不开发**；须兼容企微侧栏窄宽与现有 API。

**关联**：ClassDoc 6 原型、22 现状、23 风险、24 聊天框设计；仓库前端设计准则（避免模板化 AI 审美）。

---

## 1. 现状诊断

### 1.1 侧边栏（`apps/sidebar`）

| 问题 | 表现 |
|------|------|
| 调试台感 | Mock 表单置顶，抢主视觉 |
| 信息架构平铺 | 头区 / Tab / JSON `<pre>` 同权重 |
| 画像可读性差 | 四分区直接丢 JSON，顾问难扫读 |
| 建议/标签/日程 | 功能可用但卡片层级、主按钮不清晰 |
| 状态缺失 | 加载/空态/错误/降级无统一模式 |
| 视觉默认 | 系统字体 + 白底灰边卡片，品牌弱 |
| 结构债 | 逻辑仍偏集中；日程已拆组件可作范例 |

### 1.2 管理后台（`apps/admin`）

| 问题 | 表现 |
|------|------|
| 单页切换 | 无路由，深链/刷新丢失上下文 |
| 表格原始 | 列表信息密度与筛选弱 |
| 无设计体系 | 按钮/间距/色板不统一 |
| 客户详情 | 画像与沟通时间线未产品化呈现 |
| 登录 | 可用但无品牌落地页层级 |

### 1.3 与原型差距

ClassDoc 6 要求：侧栏头区 + Tab + 弱提示；建议区分销售/客服；日程今日/本周与 AI 待确认。  
**功能点大多已有，呈现未达到原型「顾问工具」质感。**

---

## 2. 设计原则（本项目专用）

1. **顾问任务优先**：先完成「看懂客户 → 复制话术 / 确认标签 / 确认待办」，少暴露 JSON/JobId。  
2. **AI 建议可见但克制**：统一「AI 建议」标识；主操作 ≤2 个/卡片。  
3. **Mock 不抢戏**：模拟聊天是工作台左栏（见 24），不是顶告警条。  
4. **降级诚实**：日历/强提醒/ASR Fake 用中性「能力说明」，不用红色错误恐吓。  
5. **窄宽优先**：侧栏按 360px 设计；后台按 1280px。  
6. **避免套模板审美**：不用紫白渐变万能风、奶油衬线 terracotta、报纸细线密集排版；建立**教培顾问工具**方向（见 §3）。  
7. **一区一事**：每个区块一个标题 + 一句说明 + 主内容。

## 3. 视觉方向（侧栏 + 后台共用 Token）

**主题名（建议）**：青墨工作台（Ink Mentorship）

| Token | 建议 | 用途 |
|-------|------|------|
| `--bg` | 冷灰蓝浅底 `#F3F5F8` | 页面底 |
| `--surface` | `#FFFFFF` | 面板 |
| `--ink` | `#1A2332` | 主文案 |
| `--muted` | `#667084` | 次要 |
| `--accent` | 青绿 `#0F766E` | 主按钮/激活 Tab（非紫） |
| `--accent-soft` | `#CCFBF1` | 标签芯片 |
| `--ai` | 靛灰 `#4338CA` 仅用于「AI」小标 | 不铺大面积 |
| `--warn` | `#C2410C` | 弱提醒条 |
| `--danger` | `#B42318` | 真正失败 |
| `--radius` | 10px | 面板；**避免**大圆角胶囊堆砌 |
| `--font-ui` | 「阿里巴巴普惠体 / Source Han Sans / Segoe UI」 | 屏显无衬线 |
| `--font-display` | 仅品牌名可用稍紧凑无衬线半粗 | 不抢过内容 |

动效（克制 2～3 个）：Tab 切换淡入 150ms；弱提示滑入；主按钮按压缩放。禁止光晕粒子。

品牌：首屏/顶栏出现「擎天学智」产品名（侧栏标题级，后台顶栏级），避免去掉导航后无法辨认产品。

## 4. 侧边栏 UX 方案

### 4.1 布局（对齐 ClassDoc 24）

- **演示宽屏**：左聊天 / 右能力  
- **企微窄屏**：仅能力；「会话」入口打开 Sheet  
- 弱提示：能力区顶部 sticky，不挡输入

### 4.2 客户头区

- 一行：家长 / 学员 · 年级 · 学校  
- 一行：标签 chips（最多 5，+N）  
- 顾问名与客户 ID 收入「详情」折叠，默认隐藏技术字段

### 4.3 Tab 内容改进

| Tab | 改进要点 |
|-----|----------|
| 画像 | 四分区改为可读字段卡片（基本/学情/偏好/时间线）；置信度与来源用小字；确认按区；原始 JSON 进「高级」 |
| 建议 | 场景 Segmented：销售 \| 客服；主建议大文本区；备选折叠；「基于转写」信息条；主按钮「复制」突出，「采纳/不适用」次级 |
| 标签 | 已挂标签列表 + SOP 摘要；推荐卡「建议添加/移除」分色；确认/忽略 |
| 日程 | 今日/本周 Segmented；已确认列表行内弱/强；AI 待确认区置顶星标；偏好进抽屉 |

### 4.4 反馈与空态

| 场景 | 文案示例 |
|------|----------|
| 无画像草稿 | 「暂无 AI 草稿。可在会话后点击生成画像。」 |
| 无建议 | 「暂无话术。先选场景再生成。」 |
| 生成中 | 按钮 loading + 骨架，禁止连点 |
| SSE 失败 | 非阻断黄条 |
| 日历 failed | 「已保存站内待办 · 企微日历未开通」 |

### 4.5 无障碍与操作

- 按钮可键盘聚焦；弱提示提供关闭  
- 复制成功用短暂 Toast，不 `alert`  
- 危险操作（忽略草稿）二次确认可选

## 5. 管理后台 UX 方案

### 5.1 信息架构

```
登录 → 壳层（顶栏品牌 + 用户 + 角色）
  ├─ 看板
  ├─ 客户（列表 / 详情：画像 + 时间线 + 订单）
  ├─ 员工与组织
  ├─ 订单
  ├─ 标签
  ├─ 话术模板
  └─ AI 分析（采纳率）
```

建议引入 **Vue Router**（实现阶段）；导航高亮与 URL 同步。

### 5.2 页面级改进

| 页 | 改进 |
|----|------|
| 登录 | 品牌名主导视觉 + 一短句价值主张 + 登录表单；避免纯白中框无品牌 |
| 看板 | 漏斗/续费/人效用简洁数字卡，去掉无意义装饰图 |
| 客户列表 | 筛选条 + 表格：客户、年级、标签、负责人、画像状态 |
| 客户详情 | 左画像（确认/草稿对比）右沟通与订单（可读时间线，非纯 JSON） |
| 话术模板 | 场景/学段筛选；启用态；编辑抽屉 |
| AI 分析 | 顾问采纳率表 + 按日简易趋势（可后做图） |

### 5.3 组件策略

- 试运行前可用**轻量自建**表格/抽屉，或引入一套中后台组件（Naive/Element）——**选定一种**，禁止混用两套视觉。  
- 与侧栏共享 CSS Token（§3），后台可加深侧栏导航对比度。

## 7. 分期落地建议（开发时用）

| 阶段 | 内容 | 依赖 |
|------|------|------|
| UX-0 | Token + 侧栏头区/Tab 视觉统一 | 无 |
| UX-1 | 画像可读卡片 + 建议/标签卡片层级 | UX-0 |
| UX-2 | 接入模拟聊天框布局（24） | UX-0，接口消息列表 |
| UX-3 | 后台路由 + 客户详情时间线 | UX-0 |
| UX-4 | 空态/骨架/Toast/能力状态条齐全 | UX-1～3 |

**验收主观标准**：非技术顾问 5 分钟内能完成 DEMO-01/02/05（见 ClassDoc 24），且不打开 DevTools。

---

## 8. 明确不做（本方案边界）

- 不做独立设计系统包发布  
- 不做暗色主题默认（除非客户要求）  
- 不做营销落地动效站  
- 不把后台改成卡片墙仪表盘堆砌  

---

## 9. 结论

前端当前**功能覆盖领先于体验**。试运行前应以「青墨工作台」视觉 + 可读业务卡片 +（宽屏）模拟聊天分栏，把调试壳升级为顾问工具；后台补路由与客户详情叙事。  

**本文只输出方案，不进行开发。** 评审通过后再与 ClassDoc 24 一并排期。
