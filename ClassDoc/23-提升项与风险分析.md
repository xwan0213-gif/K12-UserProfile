## 2. 必须提升（P0）

### 2.1 会话体验与 Mock 可信度 — 风险：高

**现状**：侧边栏顶部是「表单式 Mock 面板」（选客户 + 单行写入消息），不是会话流。顾问无法直观看到「聊了什么 → AI 怎么建议」。

**影响**：演示说服力弱；画像/话术/日程的输入上下文不透明；与企微真实侧边栏工作流落差大。

**提升方向**（详见 ClassDoc 24）：左右分栏「模拟聊天框 + 能力侧栏」；消息气泡、语音转写态、时间意图高亮；对齐 `/mock/messages`、ASR、SSE。

### 2.2 前端 UI/UX 产品化 — 风险：高

**现状**：双端均为单文件巨型 `App.vue` 壳 + 默认模板审美；信息密度高、层次弱；无空态/加载/错误体系；后台无路由与表格组件体系。

**影响**：试运行顾问学习成本高；反馈「像调试台不像产品」。

**提升方向**（详见 ClassDoc 25）：视觉语言、布局、交互状态、组件拆分、窄屏（企微侧栏宽度）。

### 2.3 真实企微消息路径（OPEN-01）— 风险：高

**现状**：`MOCK_WECOM=true` 为默认演示路径；真实消息增量同步未落地。

**影响**：无法在真实会话中验证画像时效与话术相关性；试运行无法替代 Mock。

**提升方向**：方案 B（回调/同步）与开关；真实最近 N 条优先；可信域名与 external_userid 联调清单。

### 2.4 集成降级的产品表达 — 风险：中～高

**现状**：日历、强提醒、真实 ASR 为 Stub/Fake；后端降级正确，前端提示偏弱。

**提升方向**：统一「能力状态条」；文案区分「功能失败」与「按设计降级」。

## 3. 重要提升（P1）

### 3.1 AI 质量与可控性 — 风险：中

| 问题 | 说明 |
|------|------|
| Prompt 无版本管理 | 散落 pipeline / Fake，难 A/B |
| DeepSeek 回退 Fake | 演示稳定但掩盖真实质量 |
| 话术模板可重复导入 | 未按 title upsert |
| 标签推荐可解释性 | UI 展示仍粗 |

**提升**：Prompt 版本号；「演示允许回退 / 试运行禁止静默回退」；模板幂等；建议卡展示来源摘录。

### 3.2 工程结构与可维护性 — 风险：中

| 问题 | 说明 |
|------|------|
| 无 Pinia/Router | 后台扩展成本高 |
| `App.vue` 过重 | 违背单文件粒度规范 |
| 后台无设计系统 | 改版成本高 |
| 测试以冒烟为主 | 缺管道单元测 / 契约测 |

### 3.3 数据范围与权限边角 — 风险：中

区域主管跨顾问查看边界、侧栏与后台字段一致性、采纳率按场景/类型下钻。

### 3.4 运维与可观测 — 风险：中

请求追踪、AI job 耗时、LLM 费用限流告警、备份与日志轮转说明不足。
