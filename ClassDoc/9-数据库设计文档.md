# 数据库设计文档

**项目**：擎天学智 · K12 用户画像推荐系统  
**文档版本**：V1.0  
**数据库**：PostgreSQL 15+（推荐）  
**字符集 / 时区**：UTF-8 / `timestamptz` 统一存 UTC，展示层转本地  
**命名**：表、字段 `snake_case`；布尔 `is_` / `has_` 前缀  
**输入依据**：`8-系统设计文档.md`、`5-软件需求规格说明书-SRS.md`（V1.1）  
**编制日期**：2026-08-07  

**关联文档**：`10-接口设计文档.md`

---

## 1. 设计原则

| 原则 | 说明 |
|------|------|
| 够用即可 | MVP 先落核心表；二期/三期表可延后建，但命名与关系一次定好 |
| JSON 存半结构化 | 画像分区、话术内容、来源列表用 `jsonb`，避免过早宽表 |
| 草稿与生效分离 | 确认前不影响看板统计；用状态字段或分表表达 |
| 业务权限非安全专项 | `owner_user_id` / `org_id` 支撑三角色数据范围，不做审计加密体系 |
| 可 Mock | `chat_message` / `order_record` 支持手工与模拟写入 |
| 埋点可统计 | `event_log` 支撑采纳率，不另建大数据栈 |

```

app_user 1──* customer                 （owner）
```

## 3. 枚举与约定

建议用 PostgreSQL `CREATE TYPE` 或 `CHECK`；MVP 可用 `varchar` + 应用层枚举，下面以类型名表达语义。

| 名称 | 取值 |
|------|------|
| user_role | `admin` / `regional` / `advisor` |
| profile_draft_status | `draft` / `partial_confirmed` / `discarded` / `merged` |
| message_direction | `in`（家长）/ `out`（顾问） |
| message_type | `text` / `voice` / `image` / `other` |
| suggestion_type | `reply` / `tag` / `schedule` |
| suggestion_status | `pending` / `shown` / `adopted` / `rejected` / `edit_adopted` / `expired` |
| schedule_priority | `high` / `medium` / `low` |
| schedule_status | `draft` / `confirmed` / `cancelled` / `done` |
| sync_state | `none` / `pending` / `synced` / `failed` |
| tag_source | `manual` / `ai` |
| order_status | `pending` / `paid` / `refunded` / `cancelled` |
| ai_job_status | `queued` / `running` / `success` / `failed` |
| event_action | 见 §5.14 |

**软删除**：核心业务表用 `deleted_at timestamptz NULL`；列表默认 `WHERE deleted_at IS NULL`。

**公共字段**（多数表）：

```sql
created_at  timestamptz NOT NULL DEFAULT now(),
updated_at  timestamptz NOT NULL DEFAULT now()
```

### 5.1 org（组织）

| 列名 | 类型 | 约束 | 说明 |

| id | bigserial | PK | |

### 5.2 app_user（系统用户 / 顾问）

| 列名 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | bigserial | PK | |
| wecom_userid | varchar(64) | UNIQUE NULL | 企微；Mock 可空或假值 |
| name | varchar(64) | NOT NULL | |
| mobile | varchar(32) | | 可选 |
| role | varchar(16) | NOT NULL | admin/regional/advisor |
| org_id | bigint | FK→org | regional/advisor 必填 |
| remind_pref | jsonb | DEFAULT '{}' | 三期提醒偏好 |
| status | smallint | NOT NULL DEFAULT 1 | 1启用 0停用 |
| deleted_at | timestamptz | | |
| created_at / updated_at | timestamptz | | |

**数据范围约定**：

- `admin`：不过滤  
- `regional`：`customer.org_id` 在所辖 org 子树  
- `advisor`：`customer.owner_user_id = app_user.id`  

```sql
CREATE TABLE app_user (
  id            bigserial PRIMARY KEY,
  wecom_userid  varchar(64) UNIQUE,
  name          varchar(64) NOT NULL,
  mobile        varchar(32),
  role          varchar(16) NOT NULL CHECK (role IN ('admin','regional','advisor')),
  org_id        bigint REFERENCES org(id),
  remind_pref   jsonb NOT NULL DEFAULT '{}',
  status        smallint NOT NULL DEFAULT 1,
  deleted_at    timestamptz,
  created_at    timestamptz NOT NULL DEFAULT now(),
  updated_at    timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX idx_app_user_org ON app_user(org_id) WHERE deleted_at IS NULL;
```

### 5.6 profile_draft（画像草稿）

| 列名 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | bigserial | PK | |
| customer_id | bigint | FK NOT NULL | |
| basic_info / study_info / prefer_info / timeline | jsonb | | 与生效同结构 |
| field_status | jsonb | DEFAULT '{}' | 如 `{"basic_info":"draft","study_info":"confirmed"}` |
| confidence | numeric(4,3) | | 0~1 |
| sources | jsonb | | `[{"type":"chat","ref":"..."}]` |
| status | varchar(32) | NOT NULL | draft/discarded/merged |
| ai_job_id | bigint | | 关联生成任务 |
| created_by | varchar(16) | | `ai` / `manual` |
| created_at / updated_at | timestamptz | | |

**规则**：同一客户允许保留历史草稿；侧边栏默认取 `status='draft'` 且最新一条。已确认字段合并进 `customer_profile` 时不覆盖已确认分区（由应用层按 `field_status` 处理）。

```sql
CREATE TABLE profile_draft (
  id            bigserial PRIMARY KEY,
  customer_id   bigint NOT NULL REFERENCES customer(id),
  basic_info    jsonb NOT NULL DEFAULT '{}',
  study_info    jsonb NOT NULL DEFAULT '{}',
  prefer_info   jsonb NOT NULL DEFAULT '{}',
  timeline      jsonb NOT NULL DEFAULT '[]',
  field_status  jsonb NOT NULL DEFAULT '{}',
  confidence    numeric(4,3),
  sources       jsonb NOT NULL DEFAULT '[]',
  status        varchar(32) NOT NULL DEFAULT 'draft',
  ai_job_id     bigint,
  created_by    varchar(16) NOT NULL DEFAULT 'ai',
  created_at    timestamptz NOT NULL DEFAULT now(),
  updated_at    timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX idx_profile_draft_customer ON profile_draft(customer_id, created_at DESC);
```

## 6. 画像状态机（数据视角）

```
[触发 generate] → 写入 profile_draft(status=draft) + ai_job
       ↓
顾问 确认字段 → 合并到 customer_profile 对应 jsonb 分区
顾问 全部确认 → 全部分区 upsert customer_profile，draft.status=merged
顾问 忽略     → draft.status=discarded
```

看板 / 话术上下文：**优先读 `customer_profile`**；无确认时可用草稿但需标记「未确认」。

## 9. 容量与可行性（粗算）

| 对象 | 假设 | 量级 |
|------|------|------|
| 顾问 | 300 | app_user 很小 |
| 客户 | 顾问×300 ≈ 9 万 | customer 表轻松 |
| 消息 | 客户×200 条约 1800 万 | 需按 customer_id+time 索引；可后期按月分区 |

| jsonb 画像 | 每客 KB 级 | 无压力 |
